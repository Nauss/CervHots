Le principe & le verdict
Faisable.

Toutes les briques existent, matures et gratuites. Le seul vrai risque n'est pas technique : c'est la lecture de la minimap par le modèle de vision.

Source d'information
Les pixels, et rien d'autre — les replays HotS ne sont écrits qu'en fin de partie. Pas d'API live.
Latence réaliste
5 à 12 secondes entre une situation à l'écran et le coach qui parle.
Format de sortie
JSON structuré + probabilités calibrées — vérifié avant de prendre la parole.

Option JEV-VL — des questions typées plutôt qu'une description libre

yes/no · choix parmi 2–16 options · note 0–5. Chaque réponse vient avec sa probabilité calibrée : le JSON est garanti par construction, et « confiance < seuil → le coach se tait » devient mesurable.

La nuance : JEV évalue, il n'extrait pas — le jeu de questions devient le vrai travail de conception. Validation sans jouer : replays en mode observateur + vérité terrain heroprotocol (lib officielle Blizzard).

CervHots07 / 09
Risques & mitigations

Où ça peut coincer

Élevé
Le modèle lit mal la minimap
Crops upscalés, few-shot avec légende du HUD, évaluation sur replays, fallback CV classique (détection de pastilles).
Moyen
Latence / dispo de l'API
Cadence 20–30 s, file latest-wins, TTS streamé — la qualité dégrade proprement, jamais bloquante.
Moyen
Conseils répétitifs ou hors-sujet
Mémoire de partie, garde-fous de prompt (« ne commenter que le visible »), cooldown entre deux prises de parole.
Moyen
pymumble vs serveurs récents
Fork maintenu en secours — et POC audio dès la phase 0 pour lever le doute tout de suite.
Faible
DPI, résolution, HUD
Profil de calibration, résolution figée — le HUD de HotS ne se déplace pas, les crops sont stables.

Pour mémoire : pixels seulement, comme OBS — aucun accès mémoire, aucun contournement.
